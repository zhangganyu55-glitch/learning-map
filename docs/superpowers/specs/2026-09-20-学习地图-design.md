## 一句话

把《五个月行动计划》那 19 周变成一张可勾选、可自己改、带可视化的进度地图，双击一个 HTML 文件就能用，数据存在本机。

## 为什么要做

用户 09-19 自评：能从零排查问题，但不能在没有教程和 AI 的情况下从空白文件写出东西。他缺的是一个每天会打开的东西——把"今天该干什么"从一份 Markdown 变成可勾选的清单，并且把卡点就地记下来。这份软件实际承担的是 `learning-log` 的角色（他至今没有建那个仓库）。

## 使用者与场景

唯一使用者是本人（大三上，每周 8–12 小时学习预算，周一至周五每天约 1.5 小时，周六集中做交付物）。典型动作：

1. 每天开工前打开，看"这周还剩什么"。
2. 学完一项，勾掉；学到卡住的地方，在当周卡点框里写一行。
3. 周六做完交付物，勾掉那条高亮的交付项。
4. 偶尔自己加一条计划外的任务（比如课程表那边冒出来的事）。

## 技术路线

单文件 HTML（`.html`），**零外部依赖、零 CDN、离线可用**。数据存 `localStorage`，并提供 JSON 导出/导入做备份。与用户已有的坦克大战、stellar-zero 保持同一交付形态：双击即开。

不选多文件 + 本地服务器（打开要先跑命令，对每日打卡太重）；不选云端同步（需要服务器与账号，超出本次范围）。

## 数据模型

```js
{
  version: 1,
  projectTitle: "学习地图",
  weeks: [
    {
      id: "w1",
      no: 1,                    // 起始周序号，用于展示
      noEnd: 1,                 // 结束周序号；15–16 周那张卡这里是 16，其余与 no 相同
      label: "9 月下旬",         // 时间提示，可编辑
      title: "第一批代码",        // 周主题，可编辑
      stage: "阶段 1 · JS 基础",
      checkpoint: null,          // 或字符串，来自原文档的阶段检查点
      tasks: [
        { id: "w1t1", text: "变量、数据类型、console.log、if、for", kind: "learn", done: false }
      ],
      note: ""                   // 卡点记录，多行文本
    }
  ],
  checkins: ["2026-09-20"]       // 每天勾掉至少一个任务就记一个日期字符串
}
```

`kind` 取值 `learn` / `deliverable` / `custom`，分别对应学习项、交付项、用户自加项，只影响样式与排序分组，不影响逻辑。

## 核心逻辑（必须可测）

单文件里用 `/* ===== CORE ===== */` 与 `/* ===== CORE END ===== */` 包住一段**不触碰 DOM、不触碰 localStorage** 的纯函数区，供 Node 测试直接抽取执行：

| 函数 | 作用 |
| --- | --- |
| `createInitialState()` | 返回预置的 19 周初始状态（深拷贝，每次调用互不影响） |
| `findWeek(state, weekId)` | 找到某一周，找不到返回 `null` |
| `toggleTask(state, weekId, taskId)` | 切换完成状态，返回新状态对象（不可变） |
| `addTask(state, weekId, text)` | 在指定周追加一条 `kind: "custom"` 任务 |
| `updateTaskText(state, weekId, taskId, text)` | 改任务文字，空字符串则忽略 |
| `deleteTask(state, weekId, taskId)` | 删除任务 |
| `moveTask(state, weekId, taskId, delta)` | 上下移动任务（delta 为 -1 / +1），越界不动 |
| `addWeek(state)` | 末尾追加一个空周，`no` 自动递增 |
| `removeWeek(state, weekId)` | 删除一周（最后一屏的周不允许删空全部，至少保留 1 周） |
| `setWeekNote(state, weekId, text)` | 写卡点 |
| `updateWeekMeta(state, weekId, patch)` | 改周主题 / 时间提示 |
| `weekProgress(week)` | 返回 `{done, total, ratio}` |
| `overallProgress(state)` | 返回 `{done, total, ratio, weeksDone, weeksTotal, currentWeekId, currentWeekNo}` |
| `currentWeek(state)` | 返回第一张还有未完成任务的周卡片（它之前的卡都算已完成）；全部完成则返回最后一张卡 |
| `toggleCheckin(state, dateISO, on)` | 记录/取消某天的打卡 |
| `streak(state, todayISO)` | 连续打卡天数（今天没打但昨天打了，仍算连续） |
| `exportJSON(state)` | 返回格式化后的 JSON 字符串 |
| `importJSON(text)` | 解析并校验；结构不对时 throw，由界面提示错误 |

所有"改状态"的函数都返回**新对象**，不原地修改，方便界面层直接替换后重绘。

术语统一：**"一张周卡片完成"= 它下面所有任务都已勾选**。因为存在两周共用一张卡的情况，`overallProgress` 统计的是**覆盖周数**：`weeksTotal` = 19（所有卡片的 `noEnd - no + 1` 之和），`weeksDone` = 已完成卡片覆盖的周数之和（所以 15–16 周那张卡一勾完，`weeksDone` 直接 +2）。

## 界面结构

单页三段式，纵向滚动：

1. **顶栏（sticky）**：左边应用名"学习地图" + 当前阶段；中间 19 格热力条，每格一周，颜色深浅表示该周完成度，点击滚动到该周；右边总进度环（SVG，`done/total` 与百分比在环中央）+ 连续打卡天数。
2. **工具条**：导出 JSON / 导入 JSON / 全部展开 / 全部折叠 / 重置为预置计划（重置需二次确认）。
3. **周卡片列表**：每张卡片= 周序号徽章、周主题（点击可就地编辑）、时间提示（可编辑）、该周进度条、任务清单、交付项、卡点输入框、加任务输入框。

任务行：左侧自绘复选框（勾选有缓动与轻微的勾线动画）；文字双击就地编辑；右侧 `↑` `↓` `✕` 三个小按钮。交付项与普通学习项在视觉上明显区分（左侧强调色竖条 + 更亮的文字）。

## 视觉方向

深色仪表盘。设计令牌：

- 底色 `#0b1020` → `#111834` 的径向渐变，叠加极淡的噪点，避免大面积纯色发闷。
- 卡片：`rgba(255,255,255,.045)` 底 + `1px rgba(255,255,255,.08)` 描边 + 大圆角（18px）+ 柔和外阴影，形成磨砂层感。
- 唯一强调色：靛青 `#6366f1` → 青绿 `#22d3ee` 的线性渐变，只用于进度环、进度条、勾选态、交付项竖条。其余全部是无彩色阶，保证不花。
- 文字：主 `#e8ecf8`、次 `#98a2b8`、弱 `#5c6780`。
- 字体：`-apple-system, "PingFang SC", "Helvetica Neue", sans-serif`，正文 14px，周主题 16px/600，数字用 `font-variant-numeric: tabular-nums`。
- 动效：进度环与进度条用 `cubic-bezier(.22,1,.36,1)` 缓动 480ms；勾选有 160ms 缩放反馈；卡片展开用高度过渡。所有动效都尊重 `prefers-reduced-motion`。
- 响应式：宽度小于 640px 时顶栏改为两行、热力条横向可滚、卡片内边距收紧。

## 数据流

`localStorage`（键 `learning-map-state-v1`）→ 启动时读取并校验 → 作为唯一状态源 → 任何操作都通过 CORE 纯函数产出新状态 → `save()` 写回 → 局部重绘。

读不到或解析失败时，回落到 `createInitialState()`，并在顶部显示一条可关闭的提示条（不弹 alert）。

## 错误处理

- JSON 导入失败：捕获异常，提示"文件不是本软件的备份，或已损坏"，状态不变。
- JSON 结构校验：必须有 `weeks` 数组且每个 week 有 `id`/`title`/`tasks`，否则视为无效。
- localStorage 不可用（隐私模式）：退化为内存态，并在顶栏提示"本次修改不会被保存"。
- 任务文字为空：忽略，不新增。

## 测试

`tests/core.test.mjs` 用 Node 内置 `node:test` + `node:assert`，零依赖。测试通过读取 `index.html`、抽取 `CORE` 标记之间的代码、在无 DOM 环境中执行，直接验证上表每个函数。覆盖：

- 预置数据完整性：17 张卡、覆盖的周序号是 1..19 且连续无缺口、每张卡至少 1 条任务、任务 id 全局唯一、第 1 周含"这周三件事"、第 6/8/10 周有 checkpoint。
- 勾选与进度：勾一条后 `weekProgress` 与 `overallProgress` 同步变化；`toggleTask` 不修改入参（不可变性）。
- 自定义：加任务 / 改文字 / 删除 / 上下移动（含边界不越界）；加周与删周（至少保留 1 周）。
- 持久化：`exportJSON` → `importJSON` 往返后状态等价；损坏 JSON 抛错。
- 打卡：`toggleCheckin` 与 `streak`（连续、断档、今天未打但昨天打了三种情形）。

界面层不做自动化测试，靠人工验收。
