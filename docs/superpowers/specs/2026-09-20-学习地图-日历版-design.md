# 学习地图 · 日历版设计稿（取代周制版）

日期：2026-09-20
状态：已与用户确认（"把19周去掉 + 首屏日历 + 点进日期看当天 + 北欧简约风"，用户回"第一种"批准了任务铺排方式）
取代：`2026-09-20-学习地图-design.md`（周制版）

## 改了什么，为什么

用户看完周制版后的原话诉求：**去掉 19 周、要无限时间、首屏是日历、点进日期才看到某一天要做什么、风格照他发的一张参考图（暖色、大圆角、克制配色）**。

周制版把"进度"绑在固定的 19 周上，实际用起来会变成"第几周了"的计数压力；改成日历后，计划退成背景，每天变成"今天这一条"，不设终点。参考图的结构（大月份标题 + 年月导航 + 月历卡 + 整宽胶囊按钮 + 日期分组列表）全部照搬，配色按北欧简约做成浅暖底。

## 数据模型

```js
{
  version: 2,
  projectTitle: "学习地图",
  tasks: [ { id, text, date: "YYYY-MM-DD", kind: "learn"|"deliverable"|"custom", done } ],
  notes: { "YYYY-MM-DD": "卡点文字" },
  checkins: ["YYYY-MM-DD"]
}
```

- 任务带日期，不再是"属于第几周"。**没有周上限、没有结束日期**，日历可以无限前后翻。
- 卡点从"每周一个"变成"每天一个"，只在该天有内容时才写入 `notes`。
- 存储键换成 `learning-map-state-v2`；旧键 `v1` 的数据不再读取（旧版备份导入时会明确报错说明格式已换）。

## 预置数据怎么落到日历上（用户选的"第一种"）

从《五个月行动计划》逐字抽出的 **53 条**任务，按原顺序**从今天开始一天一条**，不跳周末。用户选这一种是因为它省事（先铺好再改），也天然符合"无限时间"——哪天没做，任务只是往后顺延，不需要重排。

取舍说明：原计划的"阶段检查点"和"每周节奏表"依赖周的划分，日历版里没有位置，已从界面移除（原文仍在《五个月行动计划》里）；预置数据保留了 `kind: "deliverable"` 的 16 条交付物，在界面上打「本周交付物」标签。周制版里"检查点/节奏表"由 UI 承担的部分不再存在。

## 界面

单页三段，纵向滚动，宽度上限 560px 居中（接近参考图的手机比例）：

1. **月份头**：左侧大号「9月」+ 小字年份；右侧 `‹ 2026年9月 ›` 加一个回到今天的圆点按钮。
2. **月历卡**：白底大圆角卡，周一到周日表头，6×7 网格。每格：日期数字；该天有任务时，数字下方一枚小圆点（全部完成=实心沙色，有未完成=半透明），部分完成时再加一枚实心点。今天有浅沙底色，选中项有沙色描边。点任意一天即选中，页面顺势滚到当天区域。
3. **当天区域**：`9月20日 周日 · 今天` + 右侧 `当天 0/1 · 本月 0/11`；下面是当天的任务行（圆形勾选、文字、交付物标签、箭头/上下/删除按钮，触屏下按钮常显）；再往下是整宽沙色胶囊按钮「＋ 加一件事」，点了展开输入框；最后是「今天的卡点」文本框。底部一行是导出备份 / 导入备份 / 重置为预置清单。

## 视觉令牌

暖白底 `#f7f4ef`、卡片纯白、描边 `#e7e1d8`；主文字 `#2b2823`、次要 `#8a8175`、弱 `#b3aa9c`；唯一强调色沙金 `#c8a87c`，其浅色 `#efe4d3` 用于今天底色与交付物标签。圆角：卡片 22px、行 14px、按钮胶囊。阴影几乎不用，只给日历卡一层极淡的投影。字体走苹方。动效统一 `cubic-bezier(.22,1,.36,1)`，并尊重 `prefers-reduced-motion`。

## 核心逻辑（CORE，可测）

保留上一版的约定：`/* ===== CORE ===== */` 到 `/* ===== CORE END ===== */` 之间不碰 DOM 与存储，测试直接从 HTML 里抽出执行。函数：`createInitialState(todayISO)`、`tasksOn`、`findTask`、`dayStats`、`monthStats`、`toggleTask`、`addTask`、`updateTaskText`、`deleteTask`、`restoreTask`、`moveTaskToDate`、`reorderTask`、`setNote`、`getNote`、`monthMatrix`、`shiftMonth`、`shiftDate`、`weekdayIndex`、`toggleCheckin`、`streak`、`exportJSON`、`importJSON`。所有改状态的函数返回新对象。

## 错误处理

- 导入旧版（含 `weeks` 字段）的备份：明确报"这是旧版（周制）的备份，现在的格式已经换成按日期排了"，状态不变。
- 其他坏数据（缺 `tasks`、日期格式不对、空文字）：分别给出具体到第几条的错误。
- localStorage 不可用：退化为内存态并提示。
- 换日期只接受 `YYYY-MM-DD`，无效值不动。

## 测试与验收

`node --test tests/`：19 条核心逻辑断言（含 53 条预置的日期连续性、monthMatrix 的 42 格与周一起始、闰年 2 月、跨年翻月、导入导出往返等价、旧版备份报错）。

`tests/ui-smoke.html`：37 条界面断言，真浏览器跑（首屏是日历、今天有 1 件事、勾选后圆点变实心、点另一天切换、加一件事、下移、卡点落盘、换日期、删除撤销、双击改字、翻月与回到今天、刷新后状态保留、重置要两次）。

人工验收：桌面 700px 与手机 375px 两档截图确认不跑版。

## 明确不做

拖拽排序、任务重复（每天/每周循环）、提醒推送、云同步、浅色/深色切换（只做浅暖色这一套）、周视图与月视图切换。
